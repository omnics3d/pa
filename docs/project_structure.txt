ПРОЕКТ "PA" (PRICE ACTION ANALYZER)
СТРУКТУРА ПАПОК И ИХ НАЗНАЧЕНИЕ
==================================================

1. CORE/ - ЯДРО ПРИЛОЖЕНИЯ
==========================
Назначение: Основная бизнес-логика и системные компоненты.
Содержит критически важные модули, определяющие работу всего приложения.

Подпапки и файлы:
├── __init__.py             # Инициализация пакета core
├── logger_v2026.py         # Расширенная система логирования с поддержкой 
│                           # структурированных логов, ротацией файлов, 
│                           # отправкой в Sentry/Telegram
├── data_loader.py          # Универсальный загрузчик данных: загрузка
│                           # с бирж, из файлов, баз данных, API
├── basic_parser.py         # Парсеры данных: разбор свечных данных,
│                           # трансформация форматов, нормализация
├── exchange_manager.py     # Централизованное управление подключениями
│                           # к биржам: пул соединений, обработка ошибок,
│                           # реконнект, балансировка нагрузки
└── version_bumper.py       # Автоматическое управление версиями:
│                           # инкремент версий, тегирование, 
│                           # генерация CHANGELOG

Ответственность:
- Обеспечение стабильной работы приложения
- Управление подключениями и данными
- Централизованное логирование
- Валидация и обработка ошибок

2. LIB/ - ВНУТРЕННИЕ БИБЛИОТЕКИ
================================
Назначение: Переиспользуемые библиотеки и фреймворки собственной разработки.
Отдельные модули, которые можно использовать независимо от основного приложения.

Структура:
├── indicators/            # Технические индикаторы
│   ├── trend.py          # Trend indicators: MA, SuperTrend, Parabolic SAR
│   ├── momentum.py       # Momentum indicators: RSI, MACD, Stochastic
│   └── volatility.py     # Volatility indicators: ATR, Bollinger Bands
├── backtest/             # Фреймворк бэктестинга
│   ├── engine.py         # Движок бэктестинга
│   ├── metrics.py        # Расчет метрик: Sharpe, Sortino, Max Drawdown
│   └── report.py         # Генерация отчетов
├── analytics/            # Аналитические инструменты
│   ├── statistical.py    # Статистический анализ
│   ├── pattern_rec.py    # Распознавание паттернов
│   └── seasonality.py    # Анализ сезонности
└── data/                # Обработка данных
    ├── fetchers.py      # Загрузка данных
    ├── cleaners.py      # Очистка данных
    └── augmenters.py    # Аугментация данных

Характеристики:
- Высокая степень переиспользуемости
- Независимость от основного приложения
- Полное покрытие тестами
- Детальная документация
- Поддержка семантического версионирования

3. CONFIG/ - КОНФИГУРАЦИЯ ПРИЛОЖЕНИЯ
====================================
Назначение: Централизованное хранение и управление всеми настройками приложения.

Содержимое:
├── __init__.py           # Инициализация пакета конфигурации
├── settings.py           # Основной класс настроек (Settings)
│                         # с загрузкой из всех источников
├── defaults.py           # Значения по умолчанию, константы
├── app_config.yaml       # Основной YAML-конфиг: настройки приложения,
│                         # параметры алгоритмов, лимиты
├── logging.yaml          # Конфигурация логирования: форматеры,
│                         # обработчики, уровни логирования
├── exchanges.json        # Настройки бирж: API-ключи (в зашифрованном виде),
│                         # лимиты запросов, доступные пары
└── validation.py         # Валидация конфигурации: проверка целостности,
│                         # соответствие схеме, подстановка значений

Принципы работы:
- Иерархическая загрузка: .env → YAML/JSON → defaults
- Валидация при старте приложения
- Горячая перезагрузка конфигурации (где возможно)
- Шифрование чувствительных данных

10. STORAGE/ - ХРАНИЛИЩЕ ДАННЫХ
================================
Назначение: Иерархическое хранение всех типов данных приложения.

Структура:
├── temp/                # Временные файлы
│   ├── cache/          # Кэшированные данные (TTL: 1 час)
│   ├── sessions/       # Файлы текущей сессии
│   └── downloads/      # Загружаемые файлы
├── raw/                # Сырые, необработанные данные
│   ├── binance/        # Данные с Binance
│   │   ├── spot/
│   │   └── futures/
│   ├── bybit/          # Данные с Bybit
│   └── backup/         # Резервные копии
├── processed/          # Обработанные данные
│   ├── normalized/     # Нормализованные временные ряды
│   ├── aggregated/     # Агрегированные данные
│   ├── features/       # Признаки для ML
│   └── derived/        # Производные данные
├── state/              # Состояния системы
│   ├── app_state.json  # Состояние приложения
│   ├── user_prefs.json # Пользовательские настройки
│   ├── sessions/       # Сохраненные сессии
│   └── checkpoints/    # Точки восстановления
└── reports/            # Отчеты и результаты
    ├── backtest/       # Отчеты бэктестинга
    ├── analysis/       # Аналитические отчеты
    ├── exports/        # Экспортированные данные
    └── visualizations/ # Сохраненные визуализации

Политики хранения:
- temp/ очищается при перезапуске
- raw/ хранится вечно (или по политике)
- processed/ может пересоздаваться
- reports/ архивируется по датам
